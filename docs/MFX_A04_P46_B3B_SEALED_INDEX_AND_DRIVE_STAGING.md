# MFX A04/P0.46-B3-B — bounded B1 Sealed Index and SYNTHETIC-only Cloud Drive staging

**Status:** Cloud-only engineering stage pending GitHub-hosted PR and independent main CI. Owner requested continue. Parent [Issue #82](https://github.com/ngluonghoa/MFX/issues/82), child [Issue #84](https://github.com/ngluonghoa/MFX/issues/84), Cache Engine umbrella [#76](https://github.com/ngluonghoa/MFX/issues/76).

## What is implemented

1. `mfx_cache/v3_sealed_index.py` implements a single **mutable B1 latest-sealed index pointer** to SHA-named immutable B1 Manifest and 12 CLOSED M5 hourly chunk. On bootstrap it reads every B1 manifest and chunk in a bounded `<= 12000` source chain, checks ordinal SHA parents and recomputes native-source M15/M30/H1 from twelve M5. It can then advance by **exactly one new sealed B1 child** in an hourly manually triggered reconciliation; if multiple new B1 hours appeared while the index was inactive it **fails closed and requires explicitly authorized rebuild**. Raw source chunks and manifests are never deleted.
2. A HOT read with an indexed pointer uses **two direct B1 read operations** (one specific Manifest and one named chunk, both SHA checked) and **zero full historical listings**, and compares overlapping HOT candle SHA with B1 source. Mismatched candle data, missing B1 chunk, stale/forked index content, missing overlap, incorrect source chronology all fail or classify as unanchored. **An index itself is not evidence that it is the globally latest B1 Manifest** unless independently reconciled with a current listing; it is a lookup hint, not an immutable signed witness or a Google Drive CAS. B1/HOT neither authorizes official buy/sell numeric thresholds nor proves executable BID/ASK or vendor revision history.
3. `mfx_cache/v3_synthetic_drive_stage.py` defines a separate strict `SYNTHETIC_FIXTURE_NO_VENDOR_OR_MARKET_DATA` payload with integer test values, `NONE_SYNTHETIC` provider and `NONE_SYNTHETIC` symbol. It **cannot validate as actual Twelve Data EURUSD**. Two updates to one named JSON file have independent readback and SHA source checking, idempotent retry after crash following first or second write, and no provider requests or orders. One file is created only on first write; next run attempt with same GitHub run ID reuses the file.
4. `tools/mfx_drive_single_slot.py` is a restricted, exact-name/folder Drive REST adapter with duplicate/fork rejection, create/patch same file ID, required two-phase readback and fail-closed precondition. This is **cooperative single-writer validation, NOT atomic Cloud Drive compare-and-swap**. Unexpected external writers or asynchronous listing visibility remain a risk.
5. `tools/run_a04_p46_b3b_cloud_synthetic_probe.py` targets the **verified MFX-owned Google Drive staging folder** `1zJaO68XXyCApn5hBEKUqTOj7SU33d2dD`, never the protected B1 original Manifest/Chunk folders. It creates a per-GitHub-run strictly synthetic filename `MFX_SYNTHETIC_B3B_DRIVE_REPLAY_RUN_<github.run_id>.json`, logs returned file ID and two content SHA values **only if** actual authenticated Drive readback succeeded. It requires GitHub secret `MFX_GDRIVE_SERVICE_ACCOUNT_JSON` and separate repository variable `MFX_B3B_SYNTHETIC_DRIVE_STAGING_ACCEPTED=true`. It never requests the Twelve Data API, quotes, BID/ASK, source approvals or broker actions.
6. `tools/run_a04_p46_b3b_index_cloud.py` optionally reconciles the B1 index from the real private MFX B1 archive, gated by **three variables** `MFX_REAL_CACHE_ENABLED`, `MFX_V2_BATCH_CACHE_ACCEPTED`, `MFX_B3B_SEALED_INDEX_ACCEPTED`, all required to equal `true`, plus the separate GitHub service-account key. The workflow is strictly manual, no cron. It does not fetch provider data.
7. Two new workflow_dispatch-only workflows share the existing `mfx-twelvedata-private-cache` GitHub single-writer group: `.github/workflows/mfx-b3b-synthetic-drive-proof.yml` and `.github/workflows/mfx-b3b-sealed-index.yml`. The synthetic proof may run independent of vendor caching rights; the sealed index requires previously sealed B1 originals.

## What is NOT proved by code or synthetic CI

**Real authenticated Drive proof is not accomplished merely by writing this code.** Success requires an actual GitHub Actions run with a privately provisioned service account that has write permission to the identified staging folder, and receipt of a concrete, independently readable Drive file ID, two verified SHA content values, unchanged ID between PATCH and initial upload, and clean retry. If workflow skipped, lacked GH secret, or cannot list/write private staging: record a blocked result; never claim PASS. In the current conversation, Google Drive OAuth connector can read MFX staging metadata, which **does not establish** that a GitHub Actions service account can.

The B1 index uses a complete one-time bootstrap scan and still scans current B1 Manifest filenames **once per manual reconciliation**; it does not yet feed the live B3-A HOT runner automatically. Claims that all 20 pairs or native H4/D1 are indexed, or that HOT/B1 lineage forms a production-ready authoritative signal chain, are incorrect. Source rights for raw Twelve Data history/caching and executable BID/ASK/quality remain unverified ([#27](https://github.com/ngluonghoa/MFX/issues/27)); first real vendor raw price→private Drive acceptance [#74](https://github.com/ngluonghoa/MFX/issues/74) remains open; origin numeric source approval 0/16 and B2/S2 owner decisions 0/36 [#45](https://github.com/ngluonghoa/MFX/issues/45) remain pending. No Mac, MOCHI, local environment, brokerage, live user signals or release.
